# UI IMPLEMENTATION MASTER PLAN
**Project:** Wholesale BI System — Agent Edition
**Goal:** Build a production-grade, AI-powered Business Intelligence system for Indian wholesale distributors (Raj Distributors) using ERP-exported synthetic data.

## 1. Executive Summary
This document serves as the master architectural and UI implementation blueprint. It aligns the existing backend intelligence engines, the canonical synthetic ERP dataset, and a Figma-inspired visual design language into a cohesive, five-workspace Streamlit application. No backend logic or React migration is proposed; the objective is to leverage the robust Python/Streamlit stack while elevating the UX to a professional, B2B fintech standard. Revenue Recovery & Risk operates as the hero workflow.

## 2. Current Architecture Assessment
- **Frontend:** Streamlit (pp/streamlit_app.py) running a multi-page setup (now consolidated to radio buttons in a sidebar).
- **Backend:** Modular Python engines (engine/) for analytics, anomaly detection, data cleaning, forecasting, recommenders, recovery, scoring, and segmentation.
- **Data:** Canonical ERP-shaped CSVs generated by data/generate_demo_data.py. Covers 380 customers, 135 SKUs, ~24.8k transactions, and ₹45.92L outstanding.
- **State:** st.session_state manages active datasets, hashes for cache invalidation, and the AI agent chat history.
- **Verdict:** The underlying ReAct architecture, ML engines, and data pipeline are robust and production-ready. 

## 3. Current UI Assessment
- **Legacy State:** The current app used heavy gradients (#1e1e2e to #2a2a3e), large shadow blocks, and standard Streamlit defaults that felt disjointed from modern B2B SaaS.
- **UX Gaps:** Navigation is somewhat fragmented. Tables are standard pandas renders without financial tabular alignments.
- **Positives:** Stage 1 injected ui_foundation.py which provides a clean baseline of CSS, Figma tokens, and UI rendering primitives.

## 4. Figma Design System Analysis
The reference in design-reference/figma/ establishes a professional, data-dense "dark fintech" aesthetic.
- **Design Principles:** Flat surfaces over gradients; distinct border highlights for focus; strong semantic color coding for risk and status.
- **Visual Hierarchy:** 
  - ppBg (#0B0E14) as the deep canvas.
  - sidebarBg (#10141B) for navigation.
  - card (#151A23) and cardElevated (#1A202B) for data containers.
- **Typography:** Inter font family. High reliance on 	abular-nums for financial data, uppercase muted text for table headers, and 13px base sizing for density.
- **Components:** Distinct KPI tiles (ExecKpi), pill badges with 20% opacity backgrounds (e.g., success20 bg with success text), and compact action rows.

## 5. Streamlit Translation Strategy
- **How it Maps:** Figma's ExecKpi becomes ender_kpi_card(). Figma's badges become ender_status_badge().
- **CSS/HTML Usage:** st.markdown(unsafe_allow_html=True) will be heavily utilized via the ui_foundation.py wrappers to output divs and spans that perfectly mimic Figma components without requiring complex React bridges.
- **Limitations to Accept:** 
  - True client-side interactivity (like hover-reveals on rows or drag-and-drop) will be substituted with Streamlit's st.expander and standard buttons.
  - Full-page re-renders on action clicks are accepted, mitigated by aggressive @st.cache_data usage on the backend engines.

## 7. Detailed Workspace-by-Workspace Plan

### WORKSPACE 1 — ⚡ COMMAND CENTER
- **Purpose:** The executive landing page for the business owner.
- **Sections:**
  - **Business Snapshot:** CEO Morning Briefing (text generated by engine.recommender.ceo_morning_briefing), High-level KPIs (Yearly/Monthly revenue, Receivables, Inventory Value).
  - **Business Trends:** Monthly revenue trend line chart (Plotly).
  - **Territory Performance:** Bar chart mapping area sales ranking.
  - **Priority Recommendations:** Actionable ec-card list powered by generate_recommendations.
- **Interactions:** Filtering recommendations by priority (HIGH, MEDIUM, LOW).

### WORKSPACE 2 — 💳 REVENUE RECOVERY & RISK (Hero Workflow)
- **Purpose:** Permanent receivables and collections operating system.
- **Sections:**
  - **Receivables Overview:** KPIs (Total Outstanding, High Risk Amount, Expected Recovery).
  - **Immutable Ledger & Collection:** The core table combining customer risk, invoice outstanding, and recovery state.
  - **Customer Detail / Actions:** Expandable or drill-down view showing specific customer data, generating mock Razorpay links, and WhatsApp text.
- **Interactions:** 
  - Filtering by Town/Beat.
  - Selecting customers to update recovery state (IDENTIFIED → FIRST REMINDER, etc.).
  - Generating mock payment links.

### WORKSPACE 3 — 📦 INVENTORY & OPERATIONS
- **Purpose:** Logistics, stock health, and forecasting.
- **Sections:**
  - **NOW:** Inventory Health, Stockout Risk, Dead Stock (rendered as a rich table).
  - **NEXT:** Demand Forecasting (gracefully degraded if Prophet fails) & Seasonal Buying Intelligence.
  - **PERFORMANCE:** Sales & Profitability (Margin tables/charts).
- **Interactions:** Toggling between value/volume views. Expanding diagnostic details if forecasting is unavailable.

### WORKSPACE 4 — 👥 CUSTOMER INTELLIGENCE
- **Purpose:** CRM, segmentation, and geographic performance.
- **Sections:**
  - **Segmentation (RFM):** Pie chart (Champions, Loyal, At Risk, Lost) using segment_customers(compute_rfm()).
  - **Geographic Intelligence:** Town/Territory performance tables.
  - **Beat Intelligence & Churned Customers:** Compact data tables highlighting inactive accounts.
- **Interactions:** Selecting segments to view specific customer lists.

### WORKSPACE 5 — 🤖 AI BUSINESS ANALYST
- **Purpose:** Cross-workspace natural language querying.
- **Sections:**
  - Chat interface using st.chat_input and st.chat_message.
  - Suggested queries buttons.
- **Interactions:** Streaming ReAct agent trace, displaying intermediate tool calls compactly, and rendering final AI answers.

## 8. Revenue Recovery & Risk — Detailed UX Flow
1. **Discovery:** Merchant opens workspace. Top KPIs show Total Outstanding vs Total Risk.
2. **Prioritization:** The "Immutable Ledger" table defaults to sorting by Risk Level (High → Low) and Days Overdue.
3. **Filtering:** Merchant uses standard st.selectbox to filter by Town (e.g., Uniara) or Beat.
4. **Action:** Merchant clicks a "Generate Link" or "Follow Up" button for a specific customer.
5. **WhatsApp & Payment:** System reveals a generated text block containing a mock zp.io/i/... link, marked as DEMO MODE.
6. **State Update:** The customer's state in the shared_recovery session dictionary transitions (e.g., IDENTIFIED → WAITING).
7. **Ledger Update:** The UI reruns, reflecting the new badge (e.g. blue WAITING badge) in the ledger.

## 14. Known Gaps / Bugs / Integration Risks
1. **Dead Stock Statistical Improbability (BUG):** 
   * **Symptom:** UI shows 135 active SKUs, 0 dead stock, ₹0 blocked capital.
   * **Root Cause:** data/generate_demo_data.py randomly distributes 24,000 sales across only 135 SKUs over 24 months. Statistically, every SKU is sold at least once in the last 30 days (max date in dataset: 2026-08-31). detect_dead_stock classifies anything sold in the last 30 days as ACTIVE.
   * **Fix Needed (Deferred to backend phase if requested, or handled via mock):** The generator must intentionally stop selling 5-10% of items to create realistic dead stock. Do not fake UI numbers; fix the data pipeline if accurate dead stock is required.
2. **Prophet / CmdStan Environment (RISK):**
   * CmdStan is not installed. 
   * **Mitigation:** The UI *must* use ender_unavailable_state() and gracefully degrade. Do not fabricate forecasts.
